## Как сообщить об ошибке

1. Проверьте, что аналогичный issue не существует в [списке открытых](https://github.com/tsentavta/strip-dipole-cylinder/issues)
2. Создайте новый issue, используя шаблон **🐛 Bug report**
3. Заполните обязательные поля:
   - Описание ошибки
   - Шаги воспроизведения
   - Ожидаемое vs фактическое поведение
   - Версии Python и зависимостей (`pip freeze`)
   - Скриншоты или логи (если применимо)

## Как предложить улучшение

Открыто принимаются предложения о:

- **Новых функциях**: дополнительные численные методы, поддержка новых геометрий (сфера, конус)
- **Улучшениях интерфейса**: новые вкладки, дополнительные графики, экспорт в новые форматы
- **Производительности**: оптимизация, распараллеливание, использование Numba/Cython
- **Документации**: исправления, примеры использования, переводы

Создайте issue с шаблоном **✨ Feature request** и опишите идею.

## Как внести изменения в код

### 1. Подготовка окружения

```bash
# Форкните репозиторий через GitHub UI

# Клонируйте свой форк
git clone https://github.com/ВАШ-USERNAME/strip-dipole-cylinder.git
cd strip-dipole-cylinder

# Создайте виртуальное окружение
python -m venv venv
source venv/bin/activate  # Linux/macOS
# venv\Scripts\activate   # Windows

# Установите зависимости + dev-инструменты
pip install -r requirements.txt
pip install pytest pytest-cov ruff black
```

### 2. Создайте feature-ветку

```bash
git checkout -b feature/short-description
# или
git checkout -b fix/issue-number
```

**Соглашение об именовании веток:**
- `feature/...` — новая функциональность
- `fix/...` — исправление ошибки
- `docs/...` — изменения документации
- `refactor/...` — рефакторинг без изменения поведения
- `test/...` — добавление/изменение тестов

### 3. Внесите изменения

- Следуйте стилю кода, описанному ниже
- Добавьте тесты для новой функциональности
- Обновите документацию (README, docstrings)
- Делайте атомарные коммиты с осмысленными сообщениями

### 4. Запустите проверки локально

```bash
# Тесты
pytest tests/ -v

# Покрытие кода
pytest tests/ --cov=strip_dipole_cylinder --cov-report=term

# Стиль кода
ruff check .
black --check .

# Если форматирование нужно — применить:
black .
ruff check --fix .
```

### 5. Отправьте Pull Request

```bash
git add .
git commit -m "feat: добавлен расчёт КНД через интегрирование по сфере"
git push origin feature/short-description
```

Затем создайте PR через GitHub UI. **В описании PR:**

- Опишите что и зачем изменено
- Укажите ссылку на связанный issue (`Closes #42`)
- Приложите скриншоты для UI-изменений
- Подтвердите, что тесты проходят

### Соглашение о сообщениях коммитов

Используем [Conventional Commits](https://www.conventionalcommits.org/ru/):

```
<тип>(<область>): <описание>

[опциональное тело]

[опциональный футер]
```

**Типы:**
- `feat:` — новая функциональность
- `fix:` — исправление ошибки
- `docs:` — только документация
- `style:` — форматирование, точки с запятой и т.п.
- `refactor:` — рефакторинг без изменения поведения
- `perf:` — улучшение производительности
- `test:` — добавление тестов
- `chore:` — обновление зависимостей, конфигурации

**Примеры:**
```
feat(sie_solver): добавить адаптивную квадратуру по h
fix(far_field): исправить особенность при theta → 0
docs(readme): обновить инструкцию по развёртыванию
test(cylinder): добавить тест чётности Z11
```

## Стиль кода

### Python

- **PEP 8** — стандартный стиль Python
- **Black** для автоматического форматирования (`line-length = 100`)
- **Ruff** для линтинга
- **Type hints** приветствуются для публичного API
- **Docstrings в формате NumPy** для всех публичных функций:

```python
def compute_pattern(params: dict, verbose: bool = False) -> dict:
    """
    Полный цикл расчёта характеристик полоскового вибратора.
    
    Parameters
    ----------
    params : dict
        Словарь параметров (см. default_params()).
    verbose : bool, optional
        Печатать прогресс в консоль.
    
    Returns
    -------
    dict
        Словарь с результатами: 'c', 'f_arr', 'pattern_E', ...
    
    Examples
    --------
    >>> params = default_params()
    >>> result = compute_pattern(params)
    >>> print(result['Z_input'])
    """
    ...
```

### Формулы и научные обозначения

- В docstring используйте LaTeX в формате RST: `:math:` или \``\`\``
- В комментариях допустимо ASCII-приближение: `Z_11(n,h)`, `nu_m`
- Имена переменных в коде: `Z11`, `nu_m`, `xi`, `zeta` (краткие, как в формулах)
- Магические числа выносите в именованные константы

### Общие принципы

- **DRY** (Don't Repeat Yourself) — выносите повторы в функции
- **KISS** (Keep It Simple, Stupid) — простота важнее «умных» решений
- **Явное лучше неявного** — не используйте `*args, **kwargs`, если можно явно перечислить параметры
- **Безопасность по умолчанию** — защита от деления на ноль, проверка границ

## Тестирование

Все новые функции должны быть покрыты тестами. Используем **pytest**.

### Структура тестов

```python
class TestNewFeature:
    """Описание тестируемой функциональности."""
    
    def test_basic_case(self):
        """Базовый случай работает корректно."""
        result = my_function(input_data)
        assert result == expected
    
    def test_edge_case(self):
        """Граничный случай: пустой ввод."""
        with pytest.raises(ValueError):
            my_function([])
```

### Запуск тестов

```bash
# Все тесты
pytest tests/

# Только конкретный файл
pytest tests/test_cylinder.py

# Один тест
pytest tests/test_cylinder.py::TestZ11::test_z11_evenness_in_n

# С подробным выводом
pytest -v

# С покрытием
pytest --cov=strip_dipole_cylinder --cov-report=html
```

## Документация

При изменении публичного API обновите:

1. **Docstrings** функций (формат NumPy)
2. **README.md** — раздел использования
3. **CHANGELOG.md** или релиз-нотес
4. **Глоссарий** в приложении (`app.py`, `tab_glossary`), если введён новый термин

Для крупных изменений архитектуры — обновите `docs/`.
